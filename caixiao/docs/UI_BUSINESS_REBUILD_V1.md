# 采销经营驾驶舱 V1 · UI信息架构与业务前台重构说明

## 1. 本轮目标

本轮把驾驶舱从“工程能力列表”重构为“业务人员按工作任务使用的经营前台”。数据治理、接入和验证能力继续保留，但退出业务主导航；业务用户首先看到经营判断、问题、商品、库存、政策和行动。

当前页面是可运行、可交互的业务前台框架。Demo数字只用于页面和流程验证，不代表正式经营结果；真实数据缺失项继续显示“待接入”或“待确认”。

## 2. 五组业务导航

```text
01 经营总览
   ├─ 采销经营总览
   ├─ 经营异常
   └─ 今日重点
02 商品经营
   ├─ 商品经营分析
   └─ SKU 360
03 库存与采购
   ├─ 库存经营
   ├─ 报需与采购
   └─ 调拨与在途
04 政策经营
   ├─ DG任务
   ├─ 单店补贴
   └─ 政策与返利
05 行动中心
   ├─ 我的待办
   └─ 执行跟踪
```

业务板块使用固定选项：Apple线下 / APR、Apple电商、Shure电商、Apple渠道。渠道随业务板块动态变化，避免把不同经营渠道混在一个自由文本框中。

## 3. 业务页面说明

| 页面 | 首要回答的问题 | 主要呈现 |
|---|---|---|
| 采销经营总览 | 本月是否达标、库存是否健康、今天先处理什么 | 销售达成、库存周转、政策风险、今日行动 |
| 经营异常 | 哪些问题需要人工处理 | 缺货、低库存、高库存、长库龄、政策等问题池 |
| 今日重点 | 今天和本周优先处理什么 | 重点事项、SKU、建议动作、责任人、截止日期 |
| 商品经营分析 | 哪些商品畅销、慢动销或库存异常 | 商品经营表、业务标签、搜索排序分页、SKU下钻 |
| SKU 360 | 一个SKU的经营全貌是什么 | 7/14/28/90销量、三库存、双WOI、库龄、价格、政策、动作 |
| 库存经营 | 库存在哪里、是否可销、周转是否合理 | 现货、在途、经营库存、WOI、库龄与问题清单 |
| 报需与采购 | 从需求判断到采购到货走到哪一步 | 建议报需、人工确认、采购、在途、到货和分货链路 |
| 调拨与在途 | 哪些货正在调拨，何时可用 | 调出/调入、数量、状态、预计到达和逾期风险 |
| DG任务 | SI和ST任务分别完成得怎样 | DG SI、DG ST分开展示，差额和状态可追踪 |
| 单店补贴 | 每家店的目标和结算风险是什么 | 十店台账、目标/实际/差额、补贴与结算状态 |
| 政策与返利 | 还有哪些政策需要接入 | 返利、价格、返利后毛利等扩展位 |
| 我的待办 | 哪些问题已经转成执行任务 | 事项来源、SKU、动作、负责人、日期和状态 |
| 执行跟踪 | 动作执行到哪一步 | 待确认、已确认、执行中、已完成、已取消状态看板 |

## 4. 系统管理边界

系统管理只对具备相应权限的角色显示，分为：

- 数据治理：数据映射、口径管理、版本管理；
- 数据接入：吉客云、APR/客流、Shure、人工导入；
- 数据验证：Sandbox、数据质量、同步日志。

raw_code、raw_name和history_mapping继续永久只读；只有已确认且已发布的display_name和映射/口径版本才能进入正式KPI。Sandbox始终显示“验证数据，不代表正式经营口径”。

## 5. 页面与视觉规则

- PC为主工作端，导航分组可折叠，内容宽度适配常见办公屏幕。
- 手机端保留完整功能：菜单抽屉、筛选折叠、KPI卡片重排、表格横向滚动。
- 使用白/浅灰底、深蓝导航、少量金色重点；红色只用于风险，橙色只用于待处理。
- 首屏优先经营结果，不用大头图、渐变大横幅或大面积装饰占据空间。
- 同类信息保持相同卡片、状态、表格和按钮规范。
- Demo只出现一个低干扰“演示数据”提示；业务正文不出现工程术语。

## 6. 数据状态

- FORMAL：只有已确认、已发布且通过门禁的事实、映射和口径可以显示正式KPI。
- DEMO：只用于页面及交互验证，固定显示演示提示，不连接真实系统。
- SANDBOX：只用于差异和质量验证，与业务经营视图隔离。

真实数据、正式目标、阈值、政策、价格、成本、毛利、DG、补贴和返利均不得由AI虚构。未接入项按字段或模块单独显示“待接入”，不让整页空白。

## 8. 本轮验收自检

1. 业务层级能否一眼看懂：是，主导航固定为五组业务任务。
2. 首页能否在10秒内回答核心经营问题：是，先销售达成，再库存风险、政策和行动。
3. 是否减少无效大图和装饰：是，首屏没有大面积渐变和装饰头图。
4. 技术治理是否退出业务主导航：是，仅授权角色可在系统管理访问。
5. 商品问题能否进入SKU详情：是，使用URL参数下钻并可刷新恢复。
6. 库存、采购、调拨是否分工清楚：是，分别承担判断、采购流程和在途跟踪。
7. DG SI、DG ST和补贴是否混在一起：否，三者独立呈现。
8. 问题是否能进入行动：是，异常、建议动作和行动台账形成连续路径。
9. 页面是否支持PC和375px：是，浏览器回归无页面级横向溢出。
10. 业务页面是否暴露技术词：否，13个业务路由扫描为0。
11. Demo是否可能冒充正式数据：否，顶部固定演示提示且正式门禁未改变。
12. 是否已经可以生产使用：否，当前仍需PO确认、独立Review、真实数据和权限验收。

## 9. PO建议体验顺序

按以下顺序最容易判断产品逻辑是否符合业务：采销经营总览 → 商品经营分析 → 任选SKU进入SKU 360 → 库存经营 → 报需与采购 → DG任务 → 单店补贴 → 我的待办。

本轮验收只判断页面层级、业务语言、交互与信息呈现。真实数据接入、政策口径、角色权限和生产部署必须另行授权。
