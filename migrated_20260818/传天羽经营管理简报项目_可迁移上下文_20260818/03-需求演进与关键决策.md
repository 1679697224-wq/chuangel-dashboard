# 需求演进与关键决策

## 阶段一：原始简报被否

原始 Excel 已包含经营、管理、事项和风险的雏形，但问题主要不是“缺模块”，而是：

- 数据多、结论少。
- 经营结果、经营保障和行政管理混在一起。
- 日报、周报、月报只是换了时间，没有体现不同管理目的。
- 没有稳定回答原因、动作、责任、时限和老板决策。

## 阶段二：网站方向竞争

- 黄思瑞：ERP 实时取数、内网穿透、移动端与电脑端查看、风险批注和责任通知。
- 沈露奇：分端口上传模板、内部服务器、管理端与老板端、AI 接口设想。
- 用户：希望采用 Excel 收集数据，人工或 AI 汇总后上传网页，并要求中国网络环境可访问。

如未来恢复网站，还必须继承这些要求：输入固定网址即可访问、兼容手机与电脑、中国大陆网络可用、可上传统一 Excel，后续可扩展 ERP、钉钉或飞书直连。早期临时隧道和 `chatgpt.site` 曾出现中国 IP 无法访问、临时域名失效等问题，不能再作为正式方案。

这一阶段形成过统一采集 Excel、网页原型和部署包，均保留在 `03-历史方案与成果`。

## 阶段三：老板调整优先级

2026-08-17 会议明确：先不考虑网站和看板建设，先把日、周、月简报模板框架做完整。

因此当前项目主线变更为：

> 先确定经营管理框架、层级、口径、责任和闭环规则，再考虑系统化。

## 阶段四：最终第四版

用户要求：

- HTML 内容不能缺失。
- 会议纪要和第五版 Excel 用于补充。
- 至少进行三轮自检完善，交付第四版。
- 输出 Excel 和类似参考图片的框架结构图。

最终结果：

- HTML 6 层、18 模块、54 节点全部承接。
- 增加老板审阅总纲、日报/周报/月报、业务板块、管理四维、优先级、预警、AI、纪律、责任、台账、附表和来源说明。
- 完整性 54/54，公式错误 0。

## 阶段五：0817 录音会议补充（五步落地规划）

2026-08-17 会议录音（`06-会议录音转写`）补充确认老板的五步落地路径，与阶段三/阶段四并行生效：

1. 确定报表格式、内容、呈现形式（日/周/月统一「三层结构」：表头、业务板块数据、重点事项总结）。
2. 确定数据来源与获取周期（日/周/月/年；核心日+周；主抓销售、采购、库存；极客云 API 收费、按天一次取数）。
3. 使用 AI 工具并确定取数与人工审核确认流程（候选工具：Codex/GPT、小龙虾、workflow）。
4. 建立 AI 经营管理智能体框架（四职能层：销售/运维/人事行政/财务审计风控；销售职能体下挂 APR、电商等板块智能体）。
5. 沉淀 skill（把胜任优秀员工的日常工作提炼为标准 SOP 工作流）。

## 当前有效决策

- 当前不继续网站开发，除非老板重新提出。
- HTML 为第一优先级来源，第五版 Excel 为第二优先级，会议纪要为管理补充和优先级依据。
- 旧网站的视觉和技术方案可以参考，但不能反向覆盖最新框架。
- 责任端口先按岗位和部门呈现，避免因会议转写或人员调整写错姓名。
- 报表按「三层结构」执行（表头/业务板块/重点事项总结），以利润为导向。
- 经营管理智能体按四职能层搭建（销售/运维/人事行政/财务审计风控），销售职能体下按板块细分。
- 数据取数一天一次、API 直连优先；极客云 API 额度与费用需财务确认后再定对接方案。
